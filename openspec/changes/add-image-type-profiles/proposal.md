## Why

「图转图纸」是本产品的核心算法，但用户喂的图**什么都有**——网上下载的卡通 / 线稿，也有手机拍的照片。这两类图在像素化里想要**相反**的调参：

- **卡通**（平涂色、细描边）：想要**偏大 size**（保细线 / 锐边）+ **palette 合并**（吃掉边缘 anti-alias 杂色、收敛到少数意图色）。
- **照片**（连续色调、纹理）：想要**偏小 size**（把纹理平均成 291 色能表达的干净色块）+ **spatial 平滑 + palette 去杂色**。

当前系统把 size / 合并模式 / 各阈值拆成几个**孤立旋钮**，默认值是一组与图类无关的折中（palette 模式、threshold 12、size clamp 80–120）。结果：**任何单一默认对其中一类图都是次优**，用户得自己摸出「卡通往大调、照片往小调」——而「更大 = 更好」的直觉对照片恰恰是错的（更大 → 更多 291 色表达不了的高频纹理 → 更脏）。

本变更把这套专家经验固化成两个**图像类型档位**（卡通 / 照片），一键写入 size + 合并策略 + 各阈值，把「什么图都有可能」从负担变成卖点。纯客户端、零 AI。

## What Changes

- 新增**图像类型档位**（卡通 / 照片）作为「起始 bundle」：选档一次性预设 size、合并步骤、各阈值；之后用户仍可单独微调任一旋钮（**档位不锁**）。
- 合并由**模式互斥（palette XOR spatial）升级为有序流水线**（固定序 spatial → palette，每步可开关），让照片档达到「先平滑区域、再去杂色封顶」的理想态。底层 `utils/colorMerge` 已是纯函数可组合，本变更只动 store + UI，不改算法。详见 design 决策 2 的 7 个子决策。
- 档位**命名贴用户脑模型（卡通 / 照片），调参贴真实轴（色数 + 纹理方差）**。
- 每档具体数值为**经验假设**，必须配一轮真实图调参 campaign 才能定稿（见 tasks）；不做调参就上线 = 两套拍脑袋默认值，**不在本变更的完成定义内**。
- 顺手统一当前三处不一致的 size 上限（预设 ≤100 / 自动默认 120 / 滑块 200）。

## Capabilities

### Modified Capabilities

- `pattern-generation`：新增「图像类型档位」「合并流水线」两项需求；档位作为 size + 合并参数的起始预设注入现有图→网格管线。

（不改 `color-palette`：色号映射本身与图类无关。）

## Impact

- **新增 / 改动**：`src/stores/pattern.ts`（profile state + applyProfile + 合并流水线 recompute）、`src/components/pattern/Toolbar.vue`（顶部档位分段钮）、`src/utils/colorMerge.ts`（无算法改动，可能加一个组合 helper）。算法层纯函数不变。
- **客户端优先**：纯客户端，无后端、无 AI 模型。
- **数据 / 调参**：档位数值依赖实测；需准备一组代表性卡通图 + 照片作为调参集（见 tasks §4）。
- **持久化**：快照（Snapshot）v2，增 `spatialEnabled`/`paletteEnabled`（替 `mergeMode`；profile 派生、不存），含 v1→v2 迁移，跨会话恢复。
- **关联但不在本范围**：
  - 自动识别图类（②c，测色数 / 纹理方差自动选档）→ 未来独立变更。
  - 按板分页导出（MVP 任务 3.6）与 size 上限相关，但是独立变更；本变更只让「默认 size 随图类偏移」，不解决大图上限（见 design 决策 7）。
  - 拍照识别进度（P2）不在此范围。
